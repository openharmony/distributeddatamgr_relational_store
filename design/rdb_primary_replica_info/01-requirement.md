## 2. 诉求原文 🔖

> 我现在需要在relational_store中增加一个获取主备库信息，用于对比主备差异的接口。包含主备库的大小，最后一次写入的时间，如果指定了表名，要能够根据表名返回数据量

2026-10-08 第一轮澄清原文：

> 仅 Native C++ 内部接口
> 如果有binlog先尝试回放，并尝试checkpoint。然后分别返回db和wal文件大小
> 各库数据库文件或 WAL 的最后修改时间
> 是，返回精确行数

2026-10-08 第二轮澄清原文：

> 保留部分结果，如果有失败返回结果要包含失败
> connection的接口中 DB/WAL 修改时间分别返回，rdbstore中进行对比
> 是否允许并发写入期间分别采样 ？ 什么意思
> checkpoint 可能更新文件修改时间 ，获取的变更时间是在checkpoint之前。如果有binlog则获取binlog文件的最新修改时间

2026-10-08 第三轮澄清原文：

> 允许并行写入

2026-10-08 第四轮澄清原文：

> 1.是的
> 2.connection的接口返回包含db、wal文件的修改时间以及binlog的最新修改时间

其中第 1 项确认修改时间统一在 binlog 回放前采集。

2026-10-08 后续单题选项与文字澄清原文：

> 1. Unix 毫秒时间戳
> 2. 返回主备库各自的归纳时间：有 binlog 取最新 binlog 时间，否则取 DB/WAL 较大值
> 1. 全部采用上述范围
> 不涉及性能
> 3. 归档信息暂缓，本轮只明确接口行为

其中“上述范围”指：支持 MAIN_REPLICA/MANUAL_TRIGGER 两种现有主备模式及已有加密能力；可选一个普通表名；分别尝试主备 checkpoint；查询不主动触发恢复或重建。

2026-10-08 可行性分析阶段的时间归属修正原文：

> 主库只看wal文件和db文件修改时间。备库有binlog时看binlog修改时间，否则看db和wal的修改时间

备库连接策略：已有备库连接直接复用；无连接时不尝试打开，跳过依赖备库句柄的回放、checkpoint 和计数。逐项状态与失败遵循 FR-07。

## 4. 期望 🔖

| 编号 | 功能期望 | 来源依据 |
|------|----------|----------|
| FR-01 | relational_store 仅提供 Native C++ 内部接口，获取主备库信息用于主备差异对比 | 诉求原文及第一轮澄清“仅 Native C++ 内部接口” |
| FR-02 | 主库和备库分别返回 DB 主文件与 WAL 文件的大小 | 第一轮澄清“分别返回db和wal文件大小” |
| FR-03 | RdbStore 分别返回主库、备库的归纳修改时间；所有原始修改时间统一在本次 binlog 回放与 checkpoint 前采集 | 文件时间口径、回放前采集确认及单题交互对 RdbStore 返回归纳时间的选择 |
| FR-04 | 表名为可选查询条件，支持指定一个普通表；指定时分别返回主库、备库该表的精确记录行数 | 精确行数确认及单题交互对适用范围的确认 |
| FR-05 | 存在 binlog 时，采集大小和行数前先尝试回放 binlog | 第一轮澄清“如果有binlog先尝试回放” |
| FR-06 | 在尝试 binlog 回放之后分别尝试主库、备库 checkpoint，随后采集大小和行数；时间采集遵循 FR-03 | 已确认采集顺序及单题交互对主备 checkpoint 范围的确认 |
| FR-07 | 存在操作或信息获取失败时，保留可获取的部分结果，返回结果包含失败信息 | 第二轮“保留部分结果，如果有失败返回结果要包含失败” |
| FR-08 | 主库归纳时间取主库 DB/WAL 修改时间较大值；备库存在关联 binlog 时取最新 binlog 修改时间，否则取备库 DB/WAL 修改时间较大值 | 可行性分析阶段用户对主备时间归属的修正 |
| FR-09 | 信息采集期间允许并发写入，主备信息可以分别采样，不要求整组结果对应同一逻辑时点 | 第三轮对采样期间继续写入问题的确认“允许并行写入” |
| FR-10 | 备库连接存在时直接使用；无连接时不尝试打开备库，跳过依赖备库句柄的回放、checkpoint 和计数，仍返回主库可用信息 | 用户确认的备库连接策略 |
